# Подготовка задач для OpenCode

Codex-контроллер до передачи задачи изучает соответствующий код, его вызовы,
AGENTS.md и существующие проверки. Исполнитель получает самодостаточное задание,
а не только короткий запрос пользователя. Общий шаблон хранится в
[delegated-task-brief.txt](delegated-task-brief.txt).

Шаблон применяется к интерактивным контроллерам Codex/OpenCode и к операции
prepare автоматического координатора Codex. Для автоматического режима
согласованный шаг плана остаётся источником требований, allowed_paths и
test_commands: подготовка уточняет описание, но не меняет область или права.
Операция review требует сопоставить критерии приёмки с независимо изученным
кодом и результатами проверок.

Перед submit_task контроллер проверяет полноту задания по шаблону. Это требование
инструкций модели, а не новая серверная проверка качества текста. Формат MCP,
JSON-ответ prepare и совместимость существующих клиентов сохраняются.
Подробное задание не заменяет проверку diff и независимое ревью.

Для небольших изменений каждый раздел может состоять из одного предложения.
Отсутствие значимых неопределённостей указывается явно; нерешённые вопросы,
которые влияют на требования или права, разрешаются до отправки. Команды берутся
из проверенного окружения проекта; нельзя выдавать предположения за факты
или добавлять фиктивный успешный тест.

Например, критерии исправления блокировки настроек остановленного проекта:

- При задаче needs_user и остановленных процессах настройки сохраняются.
- При удерживаемой исполнителем блокировке сохранение отклоняется.
- Статус, описание и сохранённые данные задачи после изменения настроек остаются
  прежними; задачи связанных проектов сохраняются.
- Аналогичная проверка применяется к ключам провайдеров и opencode.json.

Каждый критерий связывается с конкретной проверкой. Для этой задачи существующие
тесты настроек проверяют сохранение при незавершённых задачах и отказ при
работающем исполнителе. Запуск тестов сам по себе не заменяет рассмотрение того,
покрывают ли они перечисленные сценарии.

Обновлённые инструкции загружаются при новом запуске контроллера. Открытую
терминальную сессию нужно завершить и открыть заново; /new внутри уже запущенного
Codex сохраняет инструкции, полученные при его запуске.
